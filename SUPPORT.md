# Support

Where to go when you need help with a `DashinDesign` project.

## Bug reports

Open a GitHub issue on the project in question using the bug-report template. Include:

- What you expected to happen.
- What actually happened.
- A minimal reproduction — the exact command, code, or input.
- Versions: the project version or commit SHA, plus the relevant runtime version.
- Stack trace or error output, verbatim.

Bugs without a reproduction will sit unactioned. Not out of rudeness — we can't fix what
we can't reproduce.

## Feature requests

Open an issue using the feature-request template. Describe the problem before the
solution: what are you trying to accomplish, and what's getting in the way? Concrete use
cases travel further than abstract wishlists.

## Questions and usage help

If a project has Discussions enabled, ask there. Otherwise open an issue and tag it
`question` — treat it as a conversation starter, not a bug report. If something behaved
unexpectedly but you're not sure whether it's a bug, that's a question.

## Security vulnerabilities

**Do not** open a public issue. Follow [`SECURITY.md`](./SECURITY.md) — use the
**Security** tab of the affected repository and choose **Report a vulnerability**.

## What you should not expect

- A response within a specific SLA. Best-effort only.
- Help with runtimes, platforms, or toolchains a project does not list as supported.
- Support for forks or modified distributions.

## Commercial support

No paid support tier is currently offered. Projects here are maintained by Dashin Design
s.r.o.; check each repository's `LICENSE` for what it already permits — permissively
licensed projects need no separate grant for commercial or proprietary use.
